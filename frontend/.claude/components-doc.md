# 组件文档模板

每个组件一份文档，放在组件文件夹里，文件名 `name.md`。按下面 6 节依次写，没有的内容写"无"。

## 1. 输入
组件用 `input.required<NameVM>()` 时，列出 VM 的字段。

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | `NameVM` | 整个配置对象 |
| `.field1` | type | 字段说明 |

## 2. 输出
按代码里的 `output<T>()` 写。"父组件应该"只写业务意图，不写具体函数名。

| 事件 | 参数 | 何时触发 | 父组件应该 |
|------|------|----------|-----------|
| `eventName` | type | 触发条件 | 处理逻辑 |

## 3. 双向绑定
组件用 `model.required<NameVM>()` 时，列出 VM 的字段，格式同"输入"。

## 4. 视觉状态
左边是字段，右边是受它们影响的显示部分。

| 字段A | 字段B | 显示部分1 | 显示部分2 |
|------|------|---------|---------|
| a1 | 任何 | … | … |
| a2 | b1 | … | … |
| a2 | b2 | … | … |

- **字段列**：影响越多显示部分的越靠左；能让其他字段失效的放最前
- **显示列**：顺序和字段列对应；只列会变的部分，静态标题、图标不列
- **行**：从左到右逐列分组；左边已决定结果时，右边填"任何"合并成一行
- **单元格**：用抽象词（显示 / 隐藏 / 禁用 / 可用 / 加载中 / 空状态提示），不写文案、颜色、动画等样式细节

## 5. 大小与布局
从父组件角度，按 host 上的样式写。组件内部的排列不写。

- **Width**：撑满盒子 / 按内容 / 固定值
- **Height**：撑满盒子 / 按内容 / 固定值
- **Margin**：有没有设置；没设置就紧贴盒子边框

## 6. 父组件集成示例
模板和 TS 分开写，只写和本组件有关的部分（不写 import、`@Component`）。

| 方式 | 模板 | TS |
|------|------|----|
| input | `[name]="name()"` | 持有 `name` signal |
| output | `(eventName)="handler($event)"` | 写出 handler |
| model | `[(name)]="name"` | 持有 `name` signal，给出初始值 |

示例要直观、简洁：
- 覆盖完整的状态流转，每个状态变化写一次
- 不照搬真实页面代码，用简单的假想 API（如 `this.api.getX(id)`）表达意图
- 不处理竞态、取消等与本组件无关的细节
